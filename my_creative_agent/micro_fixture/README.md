# micro_fixture

这是一个微型测试项目，用于演示 pytest 的基本使用。项目内置一个简单的计算模块（`test_calc.py`），测试其核心数学函数（如加、减等）。

## 测试

项目采用 **pytest** 作为测试框架，无需额外配置，pytest 会自动发现并运行以 `test_` 开头的测试文件。

### 运行方式

在项目目录下执行 pytest 命令：

```bash
pytest                          # 运行所有测试，显示简要结果（通过/失败）
pytest -v                       # 详细模式：逐个列出测试名称，便于确认执行了哪些测试
pytest --tb=short               # 测试失败时只显示简短错误追踪，忽略内部细节
```

### 常用参数一览

| 参数 | 作用 | 适用场景 |
|------|------|----------|
| `pytest` | 默认运行，输出简要结果 | 快速检查是否有测试失败 |
| `-v` / `--verbose` | 详细输出，列出每个测试名与状态 | 调试时确认哪些测试被实际执行 |
| `--tb=short` | 失败时只显示简短追踪 | 快速定位问题，避免冗长 traceback |
| `--tb=line` | 失败时只输出一行错误位置 | 在终端行数有限时快速定位 |
| `--tb=no` | 不显示错误追踪 | 测试全部通过，只需确认数量 |

### 示例输出

```
================= test session starts =================
test_calc.py::test_add  PASSED          [ 50%]
test_calc.py::test_sub  PASSED          [100%]
================= 2 passed in 0.04s ==================
```

> **注意**：以上输出显示 2 个测试用例全部通过。如果某个测试失败，pytest 会在对应的 PASSED 处显示 FAILED，并给出断言失败的具体行号与差异信息。

### 测试发现规则

- 项目主测试文件为 `test_calc.py`，位于项目根目录下。
- **自动发现**：pytest 会自动搜索目录下以 `test_` 开头、以 `.py` 结尾的所有文件（即 `test_*.py`），无需手动指定文件路径。
- 新增测试时，只需在根目录创建新的 `test_*.py` 文件，pytest 即可自动识别并运行，无需额外配置。
- 如需更细粒度的控制（例如只运行特定文件或跳过某些测试），可结合 `-k`、`--ignore` 等参数使用。

### 断言示例（参考）

`test_calc.py` 中的测试使用了 pytest 原生的 `assert` 断言，示例如下（仅供参考实际文件内容）：

```python
def test_add():
    assert add(1, 1) == 2

def test_sub():
    assert sub(5, 3) == 2
```

pytest 会自动将 `AssertionError` 转换为更友好的失败信息，包括实际值和预期值的对比。
