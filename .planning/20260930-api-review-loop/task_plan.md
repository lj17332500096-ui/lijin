# API 预分析、复核与一次补充循环

## 目标

在现有生产 Runtime Run 路径中加入结构化 API 预分析和执行后复核；复核明确指出缺口时，仅允许一次针对性补充执行。所有工具仍由 Runtime 执行并受现有安全门及证据契约约束。

## 阶段

1. [complete] 梳理当前主 Run 路径、路由/规划、终态与执行证据边界。
2. [complete] 定义结构化预分析/复核契约及失败、等待用户状态。
3. [complete] 将预分析和一次补充循环接入生产 Runtime，保留既有安全门。
4. [complete] 接入复核、终态记录与 TUI/API 答复呈现。
5. [complete] 完成 diff/状态静态核对并整理限制；未运行验收测试。
6. [complete] 将 Laya 提示作为 API 分析上下文中的可选建议，明确 API 决策与 Runtime 执行权边界。
7. [complete] 对明确的工作区外文件路径做 Runtime 前置检查，并把缺少 call_id 分类为模型/网关协议错误。
8. [complete] 补充决策、工具状态、复核/补充、终态及模型耗时/用量 Trace。

## 决策

- Laya 仅可选地提供前置建议；API 结构化决策是任务计划来源。
- Runtime 是唯一工具执行、安全门和执行证据权威来源。
- 补充循环最多一次；仍不完整则如实以未完成终态收束。
- 预分析/复核使用无工具、无用户 Session 的普通 JSON API 阶段，以兼容当前 OpenAI-compatible Agnes 网关；结构化结果由 Pydantic 本地校验。
- 预分析失败时回退原 Runtime 路由；复核失败或复核后仍不足时 Run 不标记完成。
- 补充需要工具时复用原 Router Agent，但仍受 Runtime 当前阶段、权限、审批和副作用幂等门控制；不新授工具权限。
- 不改动用户已有的未提交 TUI 产物交互改动。

## 风险与错误

| 项目 | 处理 |
|---|---|
| 模型输出缺字段或无效结构 | 预分析/复核解析失败时不得执行未验证计划；安全收束并记录错误 |
| 复核请求循环执行已成功副作用 | 补充计划必须绑定未完成标准/证据缺口，重复副作用仍由 Runtime 的幂等及 at-most-once 约束拦截 |
| 复核误判完成 | Runtime 证据与工具终态约束优先于模型复核意见 |

## 验收范围

- 代码路径确认预分析产生结构化决策，直接回答/询问用户/调用 Runtime 三路互斥。
- 工具计划仍通过既有 Runtime 工具门执行。
- 复核完成时输出最终稿；指出缺口时只补充一次；失败或仍不足时诚实终止。
- Trace 保留预分析、复核、补充计数和终态关联信息。
- Laya 不可用或跳过时继续由 API 正常决策；Laya 提示只进上下文和 Trace，不授予工具权限。
- 文件超出授权读取根时进入 `WAITING_USER` 并提示附加文件/切换项目目录；缺少 call_id 明确记为协议错误。
- 终态 Trace 汇总工具状态及 Run 模型调用数、token 与可用延迟字段。
- 本次不运行测试，除非用户后续明确要求验收。
