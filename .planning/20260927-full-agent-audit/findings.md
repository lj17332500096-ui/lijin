# Agent 全面检查发现

## 已确认的运行样本
- `task_2ce76fc6`（“你现在有哪些插件工具”）：路由 `capability_inventory_full_tools`，工具集合含 40 项；`extension_manager(action=list)` 连续执行 3 次，第 4 次被 convergence 拦截，Run 以 `no_progress` 失败。
- `task_fbdf0a46`（“查询不了你有什么插件吗？”）：同样走 `capability_inventory_full_tools`；先执行 `extension_manager`，之后又执行 `get_current_datetime` 和 `get_weather(city=霸州)`，最终把天气作为回答。
- 这两条记录证明实际错工具执行发生在 Runtime/路由/模型交互路径；不是单独的 TUI 重复渲染造成。

## 审计发现
### 已核对的首批结论
- 1 意图识别：两条真实 Run 都把“你有哪些插件工具”路由到能力盘点；第一条重复调用清单工具三次后失败，第二条错误调用天气工具并给出无关答复。当前工作区的修复分支已加入无工具能力上下文路径，但尚未在本轮运行验证。
- 2 Router/Layer：`runtime/tool_router.py` 有显式动作计划和工具选择护栏；现有两条 Run 说明能力盘点到执行层的隔离曾失效。`laya_router.py` 本轮需继续查明真实参与点和旁路条件。
- 5 执行证据：Runner 有执行账本、Completion Gate、终态化与事件记录；需确认“模型答复完成”与持久化副作用证据是否一致。
- 6 TUI：当前代码把失败事件只用于状态显示，最终错误统一由 RunResult 渲染；已移除 `assistant.reply` 事件的二次呈现路径。需区分静态修复与尚未复现验收。
- 7 副作用/审批：未知工具默认按有副作用、非幂等处理；审批按 ToolSpec 派生。`.env` 中审批开关为关闭状态，需核实它关闭的是交互确认还是安全门全体。
- 10 可观测性：`runtime/tool_router.py` 的 `p95_latency_ms` 实际取窗口最大值，指标名与计算不符（P2，影响成本/性能诊断）。

### 逐项静态核对
1. **用户意图/对话上下文 — 有真实 P1 失败，修复待运行验收。** 能力盘点检测已收紧为“能力关键词 + 问句形态”；Runner 在本地修复分支对能力问题只注入事实块、清空工具，并把历史截到 2 条。历史两条 Run 已证明此前能力问题可能漂移成工具调用与天气回答。检测为正则规则，覆盖范围有限，仍需逐类评估自然语言问法。
2. **Layer/Router — Laya 有限参与，边界需明确。** Laya 只对非强工具信号请求做高置信度 direct_text 短路；工具选择仍由 `select_tool_names` 完成。Laya 的 route 头尚未训练（文件头注释），生产 trace 记录 Layer、工具集合及候选计划。Layer 与 Router 的职责并非双路工具路由，但模型筛选误判仍可能清空工具。
3. **多能力流程 — 有 P1 执行编排缺口。** `infer_capability_plan` 只覆盖有限动作族；Runner 把阶段顺序追加到提示词，并写入 trace 的 `capability_plan`，尚未发现 Runtime 强制阶段完成/依赖输入的调度状态机。因此遵循顺序依赖模型，不能保证每个阶段确实执行、产出传递或失败即停。
4. **循环/重试/恢复 — 安全收口已有，失败恢复需区分。** convergence/no-progress 会终止无进展调用；真实能力查询 Run 重复清单工具三次后被拦并失败，说明现有护栏可止损但没有转成正确的直接回答。恢复代码将崩溃中副作用标成 `unknown`，避免把结果不明当成功；不同工具的可重试性和恢复后对用户的明确说明，尚缺本轮验收证据。
5. **状态/执行证据/终态 — 设计较完整，集成验收待做。** Runner 以每 Run 执行账本、事件流和副作用 WAL 汇总证据，Completion Gate 检查外部事实、写入、验证、审批声明；terminal consistency 检查终态与文案。错误主要风险在跨层集成与异常路径，不宜仅凭模块存在就认为生产行为完全一致。
6. **TUI/CLI — 重复显示修复已落代码，运行验收待做。** assistant_delta 已流式显示时 `_render_result` 会跳过重复答复；`assistant.reply` 不另行渲染；`run.failed` 事件只改状态，最终错误由结果统一渲染。用户贴出的重复答复/错误与旧路径相符，但本轮没有启动 TUI 验证显示时序。
7. **审批/安全/副作用 — 两类边界已分离。** `.env` 当前为 `APPROVAL=off`，`ApprovalGate.should_gate` 因此对需审批工具返回不拦截；工具风险目录、未知工具 fail-closed、Runner 执行账本/WAL 和其他输入/路径/预算门仍独立。该设置符合此前用户要求关闭审批；本审计只记录其实际覆盖范围，不修改设置。
8. **记忆/会话/历史隔离 — 主路径有隔离，跨层一致性未验证。** SDK 会话按 session 保存历史，Runner 的产品消息按容器和 run_id 记账；上下文压缩有软/硬阈值并记录事件。全局 Memory 本来就是跨会话记忆，属于明确共享面；本轮未做并发、多会话或摘要泄漏场景的动态验证。
9. **工具契约/插件扩展 — 有统一 ToolSpec，目录维护是风险点。** 已登记工具有副作用/风险/幂等属性，目录外工具保守默认为有副作用且非幂等；MCP 有服务/工具策略入口。静态动作计划未覆盖所有工具族，ToolSpec 和 Router 关键词规则需要一致性维护。能力清单现在在只读上下文路径上构造，仍需实跑核对 enabled/available/已配置未连接状态准确性。
10. **观测/成本/配置一致性 — P2 指标缺陷已确认。** p95 误算为最大值；本地 trace 受 `FORGE_TRACE`/CLI 显式开启控制，Router metrics 写 JSONL。可用结构化 routing/tool/completion 事件回放关键 Run；但是否能低成本默认关联请求、工具、阶段、模型耗时和预算，缺统一指标/基准证据。运行路径集中在 `runtime_paths.py`，旧 DB 回退旨在避免误开空状态库。
