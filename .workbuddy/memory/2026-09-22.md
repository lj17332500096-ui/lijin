## Phase C 实施：C3 统一错误信封 + C6 POST 守卫

归档重判后 C 阶段只剩两项（C1/C2/C4/C5/C7/C8 六项被消灭或判定有害），
且都落在 `llama_bridge.py` = 冻结层内 → 用户决策「一次做完」，属**有意开出的接口层例外**。

### 关键判断：形状由**对方**的目标反推，不是自己设计

这一轮最重要的一条方法论：**协议形状不能自定，要把消费者的解析函数反推出来**。

1. **C3 的信封形状**：报告原写「统一成 `{code,message,retryable,details,request_id}`」。
   但先把前端取错函数 `kIe()` 从 bundle 里抽出来，发现它的优先级是：
   ```
   r?.error?.message            // ① OpenAI 标准信封
   → r?.error && typeof=="string" // ② 纯字符串
   → r?.message                 // ③ 顶层 message
   → uEt[t.status] || HTTP 状态码表
   ```
   ①优先级最高 ⇒ 采用 `{"error":{message,type,code,retryable},"request_id"}`。
   **报告设想的自定形状反而会落到兜底分支**（`HTTP: 500 Internal Server Error`），
   信息量更少。→ 这就是「照报告照抄」和「按消费者反推」的差别。

2. **200 路径必须保持 `error` 是字符串**：前端对 200 里的 `error` 做 `String(a.error)`，
   传对象会渲染成 `[object Object]`。所以信封**只用于非 2xx**，工具结果仍走
   `plain_text_response`。这条约束写进了模块 docstring（否则后人会"顺手统一"）。

3. **C6 是反 CSRF，不是格式校验**。跨站 `fetch(url,{method:"POST",body:"..."})` 的
   Content-Type 默认 `text/plain`，属「简单请求」**不触发预检**、浏览器**直接投递**；
   而 `await request.json()` **不校验**类型、照样解析 body。于是任意网页都能在用户浏览器里
   触发本服务执行工具（响应读不到，但副作用已发生）。强制 JSON → 浏览器先发预检 →
   本服务不返回 CORS 头 → 实际 POST 被拦下。**删掉这个守卫 = 重新打开缺口**，
   所以注释里写了"这不是可选校验"，避免被当冗余删掉。

### 守卫的边界：只加在写端点

| 端点 | 加守卫 | 原因 |
|---|---|---|
| POST `/tools` / `/v1/chat/completions` / `.../control` | ✅ 415 | 会直接产生副作用 |
| GET `/v1/stream` / DELETE `/v1/stream` | ❌ | 无 body，前端走 `A0()` **不带** Content-Type；加了会静默打断续读 |
| `/props` `/slots` `/v1/models` `/v1/streams/lookup` `/models/*` | ❌ | 只读 |

### 一个被我自己的探针否掉的方案（重要教训）

报告写的是「**绑定断言**」，我一开始理解成**逐请求回环断言**（每个请求查 `request.client.host`）。
先写探针实测，结果：

```
TestClient 下 request.client.host == "testclient"（不是 127.0.0.1）
```

⇒ 逐请求断言会**打死全部 UI 测试**。这是典型的"看起来在加固、实际在破坏测试"。
改回报告字面意思：`webapp.main()` 启动期断言监听地址（用 `ipaddress` 覆盖 127.0.0.0/8 与 ::1），
非回环需 `FORGE_ALLOW_NONLOCAL_UI=1`。**两个守卫互补：绑定管"谁能连进来"，
Content-Type 管"同机其它页面能否借道"。**
教训通用化：**改安全守卫前，先用探针确认"被守卫的对象在测试环境里长什么样"**，
否则会把测试环境当成攻击面来加固。

### 顺带修掉一个「对方未实现」的死分支

`api_tools_execute` 命中审批门时回 `{approval_required, approval}`，而 bundle 中
这两个键命中数**均为 0** → 前端无此分支，落到 `executeTool` 的兜底 `JSON.stringify(a)`，
用户看到一坨原始 JSON（不是静默失败，兜底救了它，但也不说人话）。
现补一条**字符串** `error`（含工具名 + "待审批"），前端 `kb.ERROR` 分支会 `String()` 并标红，
`approval_required`/`approval` 保留给实现了该语义的调用方。
另补 `tool` 字段类型校验：非字符串会在 `gate.should_gate` 的集合查找里抛 `TypeError` 变成 500，
改为可读 400。

**同族残留（记入待办，本次未动）**：`api_chat_completions` 非流式路径在
`choices[0].message` 上写 `approval_required=True`（bundle 命中数同样为 0）。
但它是**附加且被忽略**的字段（正文已在 `content` 里），不造成可见缺陷；
且改 OpenAI 响应体的风险高于改桥层自有字段，故不动。
