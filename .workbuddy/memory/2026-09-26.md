## 200 条注入崩溃根因 + 修正（05:40）
- 用户 200 条 CSV（ep3_fn_patch_200_annotated）注入后 3 epoch 全崩（ep1 53.7% → ep3 8.3% 全押 text）。
- 根因定位：用 98.0% 修复版 checkpoint 在 195 条注入样本上纯推理 = 62.0%（tool 漏判 69 条 / text 全对 76 条）
  → **195 条本质是"98.0% 版的 FN 集合"**（模型判错的样本），不是"模型没见过的样本"。
  其中 83 条 text 占主导（41.5%），注入后模型被 text 先验拉到全押 text。
- 修正：只注入 112 条 tool 类（不注入 83 条 text 类），总量 5112 → 切分 train 4089 / val 511 / test 512。
  输出目录 `forge_finetuned_5112_xpu_toolonly`，任务 wuaK4S（XPU 3 epoch，~75 分钟）。
- 教训：**FN 集合不能直接当训练数据注入**——它是"模型已判错的样本"，且若 text 占主导会拉崩模型。
  正确做法：只注入"漏判的 tool"（让模型在漏判样本上再学），不注入 text 反例。
