## 真打字机逐行 emit 修复（2026-09-18 续2）
- 根因：`runtime/public_activity.py` 里 `FinalContentStream._publish` 旧实现按「完整行」trim（`decoded[:rfind('\n')+1]`），单行/无换行纯文本会退化成 0 增量、整段在 final 一帧发出，不符合"真打字机"预期
- 修复方案（安全优先折中，不是无脑 emit 全量 decoded）：
  - 非 final 帧：`text = decoded[:decoded.rfind('\n')+1]`（行边界 trim），逐字符 feed 到达新完整行边界时 emit 增量 → 多行内容逐行打字机
  - final 帧：`text = decoded`（补全剩余未发完的半截行）
  - 关键不变量：`clean.startswith(self.sent)` 前缀假设必须始终成立，否则会静默丢帧
  - 教训：曾经试过"无论 final 与否都 emit 全量 decoded"的无脑写法 → 会在 JSON 字符串值未真正闭合时，`json.loads(fragment+'"')` 的假闭包解码污染 `self.sent`，后续 `startswith` 校验失败导致后续 delta 永久丢失（`test_final_decoder_split_json_escapes_secret_and_think` 回归失败）；必须维持"未确认闭合的半截内容不进 sent"的 fail-closed 边界
- 测试：`tests/test_public_activity.py` 从 17 → 19（新增 `test_multiline_content_emits_incrementally_per_line_not_as_single_final_blob`、`test_single_line_content_still_reaches_user_via_final_frame_not_lost`），19/19 全过
- 离线验证：`scripts/verify_final_stream.py`（多行逐行emit、单行final补全、secret行过滤）3场景全过
- 附带发现（重大遗留，已修复）：`.gitignore` 第23行 `runtime/` 把**整个源码目录**当成"运行时产物"忽略了（和 logs/、data/ 那类产物规则混在一起写错），导致 `runtime/` 下所有 .py（含本次修复、CompletionGate、ApprovalGate、runner 等核心模块）全不被 git 跟踪，`git diff`/`git log -- runtime/` 全部为空。

## llama-ui 聊天链路三连修（2026-09-18 深夜）
用户报错演进：`Unexpected token '<'` → `Stream connection lost and could not be resumed` → `Stream resume produced no new bytes, giving up`，最后界面正文显示成 `json`。三个独立根因，全部已修并有回归：

1. **`/llama-ui` 前缀 API 被 SPA fallback 吞成 HTML**（`Unexpected token '<'`）
   - 前端 bundle 大量相对路径（`./props`、`./v1/models`、`./slots`、`./v1/stream`），页面挂 `/llama-ui/` 时解析成 `/llama-ui/...`，命中 `_SPAStaticFiles` 的 index.html 回落 → 前端 `res.json()` 炸。
   - 修：`llama_bridge.build_llama_ui_routes()` 补齐 `/llama-ui` 前缀端点；`webapp._SPAStaticFiles` 用 `scope["path"]`（不只 mount 内裁剪路径）识别 API-like 命名空间（props/v1/tools/slots/models/stream），保留 404 不回落。
2. **缺 OpenAI 标准 `data: [DONE]` 结束帧**（resume 系列报错）
   - 前端 bundle 里 `if(payload==="[DONE]") done=!0` 是唯一的「流正常完成」判据；我们原先只发 `chat.completion` 结束对象 → 前端认定流被中断 → 触发 stream resume → 报 LOST。加 `/v1/stream` 恢复端点返回「JSON + `data: [DONE]`」可让前端正常收口并清理 localStorage `LlamaUi.streamResume.*`。

## 后端服务「跑一阵子后整进程退出」——真凶是清理路径的 SystemExit 穿透（已修）

- 现象：`webapp.py` 启动约 27 分钟后整进程退出（后台任务 status=failed），uvicorn 打印
  `Task exception was never retrieved ... SystemExit(1)`。
- 崩溃栈：`runner._succeed` → `runner._close_run` → `provider_gateway.take_attempts`
  → `_persist_reset` → `Path.unlink` → 沙箱 `sitecustomize._check_bulk_delete_guard` → `SystemExit(1)`。

- **根因（通用教训）**：`_persist_reset` 只 `except Exception`，而 `SystemExit` 继承自 `BaseException`，
  不受 `Exception` 覆盖 → 异常穿透收尾清理 → 顺着 `run_turn/_succeed` 冒泡到 uvicorn 顶层，**打死整个服务**。
  清理是纯副作用，绝不能有能力终止进程。
- 修复（三处）：
  1. `runtime/provider_gateway.py::_persist_reset` → `except (Exception, SystemExit)`（保留 KeyboardInterrupt 不吞）。
  2. `runtime/runner.py::_close_run` → 整个函数体外层统一兜底 `except (Exception, SystemExit)`，
     一处覆盖全部 6 个 `_close_run()` 调用点；内部 `gate.clear_run` / `take_attempts` 两处同样放宽。
  3. `runtime/task_manager.py` 三处 `Path.unlink()`（删来源/删附件/去重清理旧副本）由 `except OSError` → `except (OSError, SystemExit)`。
- 新增回归：`tests/test_cleanup_resilience.py`（3 项）——mock `Path.unlink` 抛 `SystemExit`，
  断言 `_persist_reset` 不抛、`take_attempts` 仍完整返回内存记录、且 `KeyboardInterrupt` 照旧传播（保 Ctrl+C）。
- 验证：`test_cleanup_resilience + provider_deadline + provider_errors + message_attachments + sources_rag + llama_bridge` 44 passed；
  `test_task_runtime + completion_gate + obligation_gate` 66 passed。重启 8765 后实测：`/`→302、`/llama-ui/`→HTML、

### 真因（三层，全部实测确认）
1. 前端是 **SvelteKit 路径路由**，但会话走 **hash**：`/llama-ui/#/chat/<uuid>`，
   所以 `document.baseURI` 保持 `/llama-ui/`，相对路径 `./v1/xxx` 解析**正确**
   → 「子路由导致相对路径解析错」的假设被证伪。
2. 前端 bundle 里有 `XEt=3000`：`visibilitychange` 事件里，**页面变可见且距上次收到
   字节 > 3s 就 `reader.cancel()`** 掉当前 SSE（`[net-fail] net::ERR_ABORTED canceled=True`），

   用户在模型思考期间（首帧后约 7s 静默）切窗口再点回，**必然触发**。
3. 我们的适配层当时只有假占位：续读拿不到内容 → 前端报 “could not be resumed”，
   **并且该轮已生成的正文全部丢失**（实测页面文本为空）。
