## 真打字机逐行 emit 修复（2026-09-18 续2）
- 根因：`runtime/public_activity.py` 里 `FinalContentStream._publish` 旧实现按「完整行」trim（`decoded[:rfind('\n')+1]`），单行/无换行纯文本会退化成 0 增量、整段在 final 一帧发出，不符合"真打字机"预期
- 修复方案（安全优先折中，不是无脑 emit 全量 decoded）：
  - 非 final 帧：`text = decoded[:decoded.rfind('\n')+1]`（行边界 trim），逐字符 feed 到达新完整行边界时 emit 增量 → 多行内容逐行打字机
  - final 帧：`text = decoded`（补全剩余未发完的半截行）
  - 关键不变量：`clean.startswith(self.sent)` 前缀假设必须始终成立，否则会静默丢帧
  - 教训：曾经试过"无论 final 与否都 emit 全量 decoded"的无脑写法 → 会在 JSON 字符串值未真正闭合时，`json.loads(fragment+'"')` 的假闭包解码污染 `self.sent`，后续 `startswith` 校验失败导致后续 delta 永久丢失（`test_final_decoder_split_json_escapes_secret_and_think` 回归失败）；必须维持"未确认闭合的半截内容不进 sent"的 fail-closed 边界
- 测试：`tests/test_public_activity.py` 从 17 → 19（新增 `test_multiline_content_emits_incrementally_per_line_not_as_single_final_blob`、`test_single_line_content_still_reaches_user_via_final_frame_not_lost`），19/19 全过
- 离线验证：`scripts/verify_final_stream.py`（多行逐行emit、单行final补全、secret行过滤）3场景全过
- 附带发现（重大遗留，未处理，需用户决策）：`.gitignore` 第23行 `runtime/` 把**整个源码目录**当成"运行时产物"忽略了（和 logs/、data/ 那类产物规则混在一起写错），导致 `runtime/` 下所有 .py（含本次修复、CompletionGate、ApprovalGate、runner 等核心模块）全不被 git 跟踪，`git diff`/`git log -- runtime/` 全部为空。需删掉 `.gitignore` 里的 `runtime/` 一行，再 `git add -f runtime/` 补录整个目录；否则今后任何对 runtime/ 的改动都不会进版本控制。
