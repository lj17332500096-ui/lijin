# 周报生成器

## 何时触发
用户明确要求「写周报 / 周总结 / 周报生成 / 本周做了什么」时使用。其余场景不要主动套用本技能。

## 执行步骤
1. 先收集素材（按可用性依次尝试，不需要全做）：
   - `recall_memory`（近期目标/项目）、`list_notes` 与 `list_drafts` 改名后的 `list_notes`（本周产出文件）、
   - 涉及时效数据时 `get_current_datetime` 确定“本周”范围；
   - 素材不足（连用户本周在做什么都不知道）→ 用 kind=questions 问 1-3 个澄清问题，不要硬编。
2. 组织成标准周报结构：本周进展 / 数据与产出（可引用文件）/ 问题与风险 / 下周计划。
3. 产出方式：
   - 用户要“发给别人/存档” → 完整内容经 save_note 保存（文件名 周报_YYYYMMDD_主题），回复 kind=note 并给路径；
   - 只要口头看看 → kind=answer 直接给内容。
4. 结尾用 next_step 提示：是否要导出 Word（save_word_doc）或存为表格卡片。

## 边界
- 不编造：没发生的事不写“已完成”；素材缺失时如实说明并追问。
- 保留通用规则：输出仍必须是单个 AgentReply JSON；正文不堆 Markdown 符号。
- 不要重复调用工具空转：素材够一轮收集后就动笔。
