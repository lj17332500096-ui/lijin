# GitHub Token 刷新修复 - 修复记录

## 发现的问题

**文件**: `my_creative_agent/github_fetch.py`  
**位置**: 第 111-112 行  
**问题**: `_download_archive` 函数对所有 `HTTPError` 都降级到公开 API，没有区分认证错误（401/403）和服务器错误（500/502/503）。

### 当前代码（有问题）

```python
except HTTPError:
    pass
```

## 修复方案

### 修改后的代码

```python
except HTTPError as exc:
    # 只对认证错误降级；服务器错误（5xx）和其他错误直接抛出
    if exc.code not in (401, 403):
        raise
```

## 修改步骤

### 方法 1：手动编辑

打开 `my_creative_agent/github_fetch.py`，找到第 111-112 行，将：
```python
    except HTTPError:
        pass
```
替换为：
```python
    except HTTPError as exc:
        # 只对认证错误降级；服务器错误（5xx）和其他错误直接抛出
        if exc.code not in (401, 403):
            raise
```

### 方法 2：使用 Python 脚本自动修复

创建 `fix_token_refresh.py` 并运行：

```python
from pathlib import Path

GITHUB_FETCH = Path('my_creative_agent/github_fetch.py')
content = GITHUB_FETCH.read_text(encoding='utf-8')

old_code = '''    except HTTPError:
        pass'''

new_code = '''    except HTTPError as exc:
        # 只对认证错误降级；服务器错误（5xx）和其他错误直接抛出
        if exc.code not in (401, 403):
            raise'''

if old_code in content:
    new_content = content.replace(old_code, new_code)
    GITHUB_FETCH.write_text(new_content, encoding='utf-8')
    print(f"✓ 已更新: {GITHUB_FETCH}")
else:
    print("✗ 未找到目标代码，可能已修复或格式不同")
```

## 修复逻辑说明

- **401/403（认证错误）**: Token 过期或无效 → 降级到公开 API
- **500/502/503（服务器错误）**: GitHub 服务端问题 → 直接抛出异常
- **404（仓库不存在）**: 仓库不存在 → 直接抛出异常

这样可以更准确地反映问题原因，避免掩盖 GitHub 服务端故障。
