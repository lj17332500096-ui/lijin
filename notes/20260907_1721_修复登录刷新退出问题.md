# 修复：登录后刷新页面会退出

## 问题描述
用户登录后刷新页面，认证状态丢失，被迫重新登录。

## 根因分析
`src/session.ts` 中的 `SessionStore` 类注释明确指出已知缺陷：
> token 只保存在内存，刷新页面后丢失 → 表现为"登录后刷新页面会退出"

查看代码确认：`saveToken` 和 `loadToken` 方法使用了 `localStorage`，但代码注释说明本应使用 `sessionStorage`。

另外，`src/auth.ts` 中的 `AuthClient` 在登录和刷新 token 后，仅将 token 保存到内存变量 `this.token`，没有调用 `SessionStore` 进行持久化。

## 修复内容

### 1. src/session.ts - 修正存储方式
将 `localStorage` 替换为 `sessionStorage`（更安全，标签页关闭后自动清除）：
- `saveToken`: 从 `localStorage.setItem` 改为 `sessionStorage.setItem`
- `loadToken`: 从 `localStorage.getItem` 改为 `sessionStorage.getItem`
- `clear`: 从 `localStorage.removeItem` 改为 `sessionStorage.removeItem`

### 2. src/auth.ts - 添加持久化调用
- 导入 `SessionStore`
- 在 `login()` 成功后调用 `SessionStore.get().saveToken(data.token)`
- 在 `refresh()` 成功后调用 `SessionStore.get().saveToken(data.token)`
- 添加构造函数，页面加载时从 `sessionStorage` 恢复 token

### 3. tests/auth.test.ts - 更新测试
- 新增断言验证 token 已保存到 sessionStorage

## 为什么用 sessionStorage 而不是 localStorage
- `sessionStorage` 在页面会话期间保持数据，关闭标签页后自动清除，更安全
- `localStorage` 永久存储，即使关闭浏览器也保留，不适合敏感 token
- 对于"登录后刷新页面不退出"的需求，两者都能工作，但 `sessionStorage` 更符合安全最佳实践
