# 修复：登录后刷新页面会退出

## 问题描述
用户登录后刷新页面，认证状态丢失，被迫重新登录。

## 根因分析
`src/session.ts` 中的 `SessionStore` 类注释明确指出已知缺陷：
> token 只保存在内存，刷新页面后丢失 → 表现为"登录后刷新页面会退出"

查看代码确认：`saveToken` 和 `loadToken` 方法使用了 `localStorage`，但代码注释说明本应使用 `sessionStorage`。

另外，`src/auth.ts` 中的 `AuthClient` 在登录和刷新 token 后，仅将 token 保存到内存变量 `this.token`，没有调用 `SessionStore` 进行持久化。

## 修复内容

### 1. src/session.ts - 修正存储方式
```typescript
// 修复前
saveToken(token: string): void {
  // FIXME(known-bug): 刷新后丢失，应改用 sessionStorage
  localStorage.setItem(this.tokenKey, token);
}

loadToken(): string | null {
  return localStorage.getItem(this.tokenKey);
}

clear(): void {
  localStorage.removeItem(this.tokenKey);
}

// 修复后
saveToken(token: string): void {
  sessionStorage.setItem(this.tokenKey, token);
}

loadToken(): string | null {
  return sessionStorage.getItem(this.tokenKey);
}

clear(): void {
  sessionStorage.removeItem(this.tokenKey);
}
```

### 2. src/auth.ts - 添加持久化调用
```typescript
import { SessionStore } from "./session";

// login 成功后
SessionStore.get().saveToken(data.token);

// refresh 成功后
SessionStore.get().saveToken(data.token);
```

## 为什么用 sessionStorage 而不是 localStorage
- `sessionStorage` 在页面会话期间保持数据，关闭标签页后自动清除，更安全
- `localStorage` 永久存储，即使关闭浏览器也保留，不适合敏感 token
- 对于"登录后刷新页面不退出"的需求，两者都能工作，但 `sessionStorage` 更符合安全最佳实践
