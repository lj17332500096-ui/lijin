```markdown
# 读书笔记技能

## 用途
帮助读者快速梳理书籍核心内容，将阅读收获转化为可执行的个人行动。

## 触发条件
- 用户要求"写读书笔记"、"帮我总结这本书"
- 用户提供书名/章节/PDF/链接，要求整理笔记
- 用户要求"提取这本书的重点"

## 核心流程

### 1. 获取书籍信息
- 若用户提供完整信息 → 直接使用
- 若仅提供书名 → 用 web_search 补充作者、出版社、评分等基础信息
- 若用户提供 PDF/Word → 用 read_office_file 读取内容

### 2. 提取核心内容
根据输入类型灵活处理：
- **章节摘录**：直接分析用户提供的文字
- **完整书籍**：用 web_search 搜索书籍概要 + 豆瓣/知乎书评交叉验证
- **PDF/文档**：提取关键章节内容，聚焦核心论点

### 3. 生成结构化笔记
输出以下 6 个模块：

| 模块 | 内容 | 数量建议 |
|------|------|---------|
| 📖 基本信息 | 书名、作者、一句话概括 | 必填 |
| 🎯 核心观点 | 书中最重要的 3-5 个论点 | 每条附依据 |
| 💬 金句摘录 | 最有价值的原句 | 3-5 条 |
| 💡 启发反思 | 读者的个人思考 | 可选 |
| ✅ 行动清单 | 具体可执行的事项 | 按优先级 |
| ❓ 待解决 | 书中未解答或存疑点 | 可选 |

### 4. 保存与归档
- 询问用户是否保存到 notes 目录
- 文件命名：YYYYMMDD_书名_读书笔记

## 输出格式
- 默认 Markdown 格式
- 用户指定 Word/PDF 时可用 save_word_doc / pdf 技能转换

## 约束
- 忠实于原著，不虚构书中没有的内容
- 引用的观点需注明章节或页码（如有来源）
- 金句摘录不得超过原文 20%
- 行动项必须具体可执行（避免"多读书"类空话）
- 个人启发部分需明确区分「书中内容」与「用户自己的思考」

## 相关工具
- web_search：补充书籍信息
- read_office_file：读取 PDF/Word 内容
- save_note：保存笔记到 notes 目录
- save_word_doc：生成 Word 格式笔记
```

## 设计建议

### 1. 输入灵活性
支持多种输入方式，避免单一依赖：
- 纯书名 → 搜索补充
- 章节摘录 → 直接分析
- 完整文档 → 读取提取

### 2. 输出标准化
固定 6 模块结构，确保笔记质量稳定，降低 AI 输出波动。

### 3. 可扩展性
后续可增加：
- 对比阅读（两本书对比）
- 复习提醒（定时推送）
- 批注导出（生成 PDF 版）

### 4. 协作现有工具
- `read_office_file`：读取书籍文档
- `web_search`：补充书籍信息
- `save_note`：保存笔记
- `save_word_doc`：生成 Word 版本
